# 技术文档: 基于Prompt工程的上市公司财报解读与行业对标系统

> 版本: v1.0 | 日期: 2026-08-14 | 后端完成度: 100%(接口全部实测通过)

---

## 1. 项目概述

面向普通投资者的上市公司财报智能分析工具。核心思路是**双层解耦架构**:

```
┌─────────────────────────────────────────────────────────────┐
│  上层: 智能解读层                                             │
│  三层Prompt(角色设定+数据注入+输出约束) → 大模型 → 自然语言报告 │
│  严格基于注入数据生成, 禁止编造数字(防幻觉)                    │
├─────────────────────────────────────────────────────────────┤
│  下层: 数据计算层(本后端全部实现)                              │
│  原始财务数据 → 12项标准化指标 → 行业对标(均值/中位数/百分位)   │
│  → 多条件交叉筛选 → 排名 → 画像/趋势                           │
│  每一个数字均可溯源、可验证                                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 与原始骨架的差异(数据库变更)

1. **新增表 `解读报告`**: 原 8 张表之外新增, 用于持久化 AI 简报与多轮对话(含注入的数据上下文, 可审计模型是否捏造数据)
2. **`报表项目` 由 20 项增至 22 项**: 新增 `current_assets_total 流动资产合计`、`current_liabilities_total 流动负债合计`, 使流动比率/速动比率可以**精确计算**而非近似估算
3. **数据重置并扩充**: 原库仅有 1 个行业/1 家公司/52 条原始数据且年度不完整; 现为 3 行业 × 24 家公司 × 5 年(2021-2025) × 22 科目 = **2640 条原始数据** + 48 条估值快照 + 3 条 Prompt 模板
4. 默认数据为**真实财报数据**(东方财富/新浪公开接口采集, 采集脚本 `sql/fetch_real_data.py`); 重新采集后替换 `财务原始数据`/`估值快照` 并重算

## 4. 指标体系 (12 项, 定义见 `common/IndicatorDef.java`)

| 维度 | 指标编码 | 名称 | 单位 | 方向 |
|---|---|---|---|---|
| 盈利能力 | roe | 净资产收益率 | % | higher_better |
| 盈利能力 | gross_margin | 毛利率 | % | higher_better |
| 盈利能力 | net_margin_parent | 归母净利率 | % | higher_better |
| 成长性 | revenue_growth | 营业收入增长率 | % | higher_better |
| 成长性 | profit_growth | 归母净利润增长率 | % | higher_better |
| 财务风险 | asset_liability_ratio | 资产负债率 | % | lower_better |
| 财务风险 | current_ratio | 流动比率 | 倍 | higher_better |
| 财务风险 | quick_ratio | 速动比率 | 倍 | higher_better |
| 盈利质量 | cashflow_quality | 经营现金流/净利润 | 倍 | higher_better |
| 每股指标 | eps | 基本每股收益 | 元/股 | higher_better |
| 估值 | pe | 市盈率 | 倍 | lower_better |
| 估值 | pb | 市净率 | 倍 | lower_better |

**计算公式** (`service/calc/IndicatorCalcEngine.java`):

| 指标 | 公式 | 备注 |
|---|---|---|
| roe | 归母净利润 ÷ 平均股东权益 × 100 | 平均 = (上年末+本年末)/2, 无上年用期末 |
| gross_margin | (营业收入−营业成本) ÷ 营业收入 × 100 | |
| net_margin_parent | 归母净利润 ÷ 营业收入 × 100 | |
| revenue_growth | (本期营收−上期营收) ÷ \|上期营收\| × 100 | 首年无 |
| profit_growth | (本期归母净利−上期归母净利) ÷ \|上期\| × 100 | 首年无 |
| asset_liability_ratio | 总负债 ÷ 总资产 × 100 | |
| current_ratio | 流动资产合计 ÷ 流动负债合计 | |
| quick_ratio | (流动资产合计−存货) ÷ 流动负债合计 | |
| cashflow_quality | 经营现金流净额 ÷ 净利润 | |
| eps | 直接取报表项 eps_basic | |
| pe | 总市值 ÷ 归母净利润 | 需同年估值快照 |
| pb | 总市值 ÷ 股东权益 | 需同年估值快照 |

## 5. 行业对标引擎 (`service/calc/BenchmarkCalculator.java`)

**统计基准**(按 行业×年度×指标 计算, 样本 = 同行业全部公司):
- 均值(算术平均)、中位数、P25/P75(线性插值分位)、总体标准差、样本数

**公司定位**:
- 原始百分位 percentile = `(严格小于公司值的样本数) ÷ (样本数−1) × 100`(单样本或全等时取 50)
- 方向评分 score: higher_better → score = percentile; lower_better → score = 100 − percentile(评分越高越优, 便于横向比较)
- 排名 rank: higher_better 值最大为第 1; lower_better 值最小为第 1(并列同名次)

结果同时落库 `行业对标`(重算时批量写入), 查询时实时计算保证与指标表一致。

## 6. 多条件交叉筛选 (`POST /api/finance/screening`)

- 条件之间 AND 关系, 支持运算符:
  - `gt / gte / lt / lte` 数值比较
  - `between` 区间(value, value2)
  - `pct_gt / pct_lt` 行业百分位过滤(揭示"单一指标难以发现的隐藏财务信号", 如"ROE 处于行业前 20%")
- 支持限定行业(缺省全市场), 返回每家公司的逐条件判定明细(passed/actualValue)

## 7. Prompt 工程设计与 AI 模块

### 7.1 三层 Prompt 模板(存于 `提示词模板` 表, 代码内置同款默认兜底)

1. **角色设定层**: 资深 CFA 财务分析师, 客观严谨、结论必须有数据支撑
2. **数据注入层**: 将系统精确计算的 12 项指标 + 行业基准 + 百分位/排名序列化为 JSON, 并声明"这是本次分析唯一可信的数据来源"
3. **输出约束层**: 只准使用注入数据、固定六段式结构、每章必须引用具体数值、缺数据必须明说"数据不足"、≤800 字、中文 Markdown —— 从指令层面抑制幻觉

### 7.2 流程

```
FinanceService.getBenchmark()  →  buildDataJson()  →  composeSystemPrompt(角色+数据注入)
                                                            ↓
         mock 规则引擎(离线)  ←  降级  ←  LLM 调用(OpenAI兼容: DeepSeek/通义/智谱…)
                                                            ↓
                                          保存到 解读报告(含 context 审计)
```

### 7.3 LLM 接入配置 (`application-development.properties`)

```properties
ai.provider=mock          # mock=离线规则引擎(无需Key); openai=OpenAI兼容接口
ai.base-url=https://api.deepseek.com/v1
ai.api-key=               # 填 Key 后自动切换真实大模型
ai.model=deepseek-chat
ai.temperature=0.3
ai.timeout-seconds=60
```

- 调用失败自动降级 mock, 服务不中断
- **mock 引擎同样只输出注入数据中的数字**, 演示"数据锚定 + 指令约束"防幻觉方案
- 多轮对话(`POST /api/ai/chat`)携带 history + 同一数据上下文, 支持针对特定指标的追问

## 8. 接口清单 (15 个, 详见 `docs/接口设计表.md`)

财务模块 `/api/finance`:
- GET `/industries` 行业列表(含公司数)
- GET `/companies` 公司分页(keyword/industryId/status)
- GET `/companies/{id}` 公司详情
- GET `/profile` 财务画像(原始科目+指标+估值)
- GET `/trend` 多年度指标趋势
- GET `/benchmark` 行业对标(核心: 值/基准/百分位/评分/排名)
- GET `/ranking` 行业指标排名
- POST `/screening` 多条件交叉筛选
- POST `/recalc` 重算指标与行业对标(数据变更后执行)

AI 模块 `/api/ai`:
- GET `/templates` 三层 Prompt 模板
- POST `/report` 生成财报解读简报
- POST `/chat` 上下文感知追问对话
- GET `/reports` 报告/对话记录分页
- GET `/reports/{id}` 报告详情

统一响应 `{code, message, data}`, code=0 成功; 错误码见 `ErrorCodeEnums`。

## 10. 环境适配记录 (本机踩坑与解决)

| 问题 | 原因 | 解决 |
|---|---|---|
| Lombok 不生成 getter/setter | JDK 23+ 默认不执行 classpath 注解处理器 | 编译器插件配 annotationProcessorPaths + `-proc:full`, Lombok 升 1.18.46 |
| DruidDataSourceBuilder 找不到 | druid 1.2.20 jar 中无此类; 且该 jar 曾下载失败 | `mvn dependency:get` 手动拉取; 改为 `new DruidDataSource()` |
| Failed to determine a suitable driver | @SpringBootApplication 默认只扫自身包, 扫不到 com.fycx.config | `scanBasePackages="com.fycx"` |
| PowerShell 下 curl POST 中文 JSON 报错 | PS 5.1 单引号参数转义问题 | 用 `--data-binary @file.json` |
| 端口 8091 被占用 | 验证后遗留后台实例 | 停止遗留进程 |
